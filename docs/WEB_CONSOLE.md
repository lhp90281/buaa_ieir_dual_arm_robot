# 本地网页控制台

统一入口 `ui.launch.py` 可按操作者确认启动/停止控制端、标定、主从遥操作和回放。
**bridge 仍手动启动，网页不配置 CAN、不管理 bridge，不在打开页面时使能电机。**
控制和标定复用现有算法；标定全手动，不自动寻限位或回零。旧的只连接模式仍保留。

## 安装与启动

在 W3 工作区的新终端执行，不叠加全身版工作区：

```bash
cd ~/ros2_ws/w3_dual_arm_ws
source /opt/ros/humble/setup.bash
colcon build --base-paths src --packages-select ieir_controllers ieir_bringup
source install/setup.bash
# 终端 A：使用本机 CAN 配置和与 UI 相同的 ROS_DOMAIN_ID
ros2 launch ieir_bringup bridge.launch.py arms:=dual gripper:=false
```

另开终端 B：

```bash
cd ~/ros2_ws/w3_dual_arm_ws
source install/setup.bash
ros2 launch ieir_bringup ui.launch.py workspace:="$PWD" gripper:=false
```

浏览器打开 http://127.0.0.1:8766 。端口占用时加 `port:=8767`，不要结束不属于本 UI 的进程。
启动 UI 只观察 ROS；打开“允许控制”后，在总览选择双臂/左臂/右臂，确认“启动控制端”。
这一步才加载本机标定、使能所选电机并进入重力补偿。之后网页切换关节/笛卡尔模式。
如果尚未完成标定，先进入标定页，不必启动控制端。

后端使用标准库 HTTP server、rclpy 和已声明的 ROS 消息依赖，不需要 rosbridge、Node.js、npm、pip 或 CDN。
Three.js/Lucide 和许可证已打包；STL/URDF 使用 workspace/src/description。
不要删除源码 description/ros2_ws_config 后仅搬 install。装了夹爪需给 bridge 和 UI 都加 `gripper:=true`。
UI 会把相同参数传给它启动的控制端；不会修改外部已运行控制器的模型。

兼容入口：也可直接启动控制器并附带只连接网页（不要和总 UI 同时运行同端口）：

```bash
ros2 launch ieir_bringup real_robot.launch.py \
  arms:=dual gripper:=false controller:=gravity use_web:=true web_allow_control:=true
```

这个组合命令会启动控制器并使能电机，附带网页地址 http://127.0.0.1:8766 。
这个兼容入口附带的网页不管理进程；需要完整交互式启动/标定时使用上面的 `ui.launch.py`。
`web_port` 默认 8766，`web_workspace` 默认当前工作目录，`web_allow_control` 默认 false。
`use_web` 默认 true；旧 `use_gui` 是兼容默认值，已不再启动 MuJoCo 面板。
只需要后台控制器用 `use_web:=false`；已经单独运行网页时也不要重复启动同一端口。
真机控制台和默认标定完全不依赖 MuJoCo。兼容 MuJoCo 显示器已移至可选的
`simulation/ieir_simulation`，安装方式见 [仿真手册](../simulation/README.md)。

需要网页控制时，结束只读网页服务后重新启动：

```bash
ros2 launch ieir_bringup web_console.launch.py workspace:="$PWD" allow_control:=true
```

网页还需开启“允许控制”，每次操作再确认。切到后台/连接断开会锁定页面。
**锁定/关闭浏览器不会暂停已有控制器、已发轨迹或遥操作。**
例外是网页模式标定：页面隐藏/关闭或失联后，心跳超时会中止标定并尝试失能。
停止 UI 服务进程会向其自有子进程发 SIGINT，先退出标定/遥操作/回放，再退出控制端。
退出控制端可能失去支撑力，关 UI 服务前须支撑全臂；bridge 和外部进程不被停止。
网页不是急停器；没有未经确认的全臂失能按钮，避免无支撑时突然下落。

只看界面、不连接 ROS：

```bash
ros2 launch ieir_bringup web_console.launch.py workspace:="$PWD" preview:=true
# 不需要 ROS 环境的等价源码入口：
python3 src/ieir_bringup/scripts/web_console.py --workspace "$PWD" --preview
```

预览模式标为合成数据，不导入 ROS、不打开 CAN；切模式和关节目标只改变本地演示。
预览不伪造末端 TF、标定或真机服务成功。

## 功能与接口

| 页面 | 行为 |
|---|---|
| 运行总览 | 启停自有控制端、进程退出状态、完整 URDF/STL 模型、关节/W3 反馈、控制器状态、TF、日志 |
| 控制器 | STRICT 切换关节/笛卡尔接口，始终保留或激活 gravity_compensation_controller，不卸载硬件 |
| 总览 → 回零 | 左臂/右臂/双臂回到标定后的模型 0°；确认后自动切关节位置，保留重力前馈 |
| 关节控制 | 读取当前、角度输入与滑块、目标预览、发送单臂 JointTrajectory 和插值时间 |
| 末端控制 | 读取 base_footprint 到 attachment_point 的实时 TF，输入绝对 XYZ/RPY，再发送 PoseStamped |
| 主从遥操作 | 配置本机角色、对端 IPv4、端口，启停 no_feedback 节点，再分别确认 prepare/enable/disable/exit |
| 关节标定 | 启停方向/限位/手动采样、网页修改参考角、确认与增量预览、双臂合并，无需 MuJoCo 窗口 |
| 示教记录 | 只读采样 /joint_states，20 Hz、最多 120 秒；网页启停原 teach_replay 回放（0.5 倍速、5 s 进入起点） |
| 运行配置 | 文件存在/解析检查，不回传零偏内容，不修改本机标定文件 |

总 UI 和终端标定现在都默认 `--preview-backend web`，不打开 MuJoCo。
从终端启动时需已有网页控制台，打开标定页并保持页面可见以提供心跳；推荐直接从总 UI 启动标定。
只有显式 `--preview-backend mujoco` 才调用可选仿真包的兼容显示器。
“确认”可能使能当前关节或保存标定，必须核实会话、支撑和当前阶段；不要在两个窗口同时按键。
多个会话时必须核实下拉框和完整状态。

### 从控制切换到标定

1. 网页先停止遥操作/回放节点，支撑全部关节，再确认“停止控制端”并检查失能；保留唯一的 W3 bridge。
   仅在网页切到重力补偿不等于停控制器，不能这样直接进入标定。
2. 打开“关节标定”，选择左/右臂和“方向确认”，启动并确认。模型从零位开始，
   首次确认捕获显示基准；手动小幅移动当前关节，不一致点“翻转方向”，一致点“确认”进入下一关节。
   方向阶段使能所选整臂、全零阻抗，须支撑所有关节。全部确认才保存 directions。
3. 选择“限位参考”并启动。网页显示当前关节参考角，可输入度数、点“更新参考角”，再“确认”。
   此阶段不发电机命令；确认全部七项后保存 reviewed 文件。
4. 选择“手动采样”，可选全部关节或单一关节，启动后视图自动切到“标定”。
   顺序为 7、6、5、3、4、2、1；首次确认仅使能当前关节零阻抗反馈。
   将实物手推到限位并停稳，再确认采样保存；保存后手动移动核对显示，“下一项”继续，“跳过”保留已有结果。
   没有自动回零或二次寻限位。第 4 关节先调整并支撑第 3 关节，避开支架。
5. 两臂完成并退出全部标定后，选择“双臂合并”启动。退出码 0 表示合并脚本成功。
   返回总览重新启动控制端加载新文件，不需重新编译。单臂启动直接读取该臂 offsets 文件。

已有正确的方向和 reviewed 文件时可从手动采样开始。各关节即时保存到单臂文件，双臂合并仍是显式操作。
写入前备份已有文件到 `workspace/log/web_calibration_backups/`，不上传 Git。
不要关闭/隐藏页面进行标定；心跳约 0.5 秒，浏览器消失后约 3–5 秒触发退出清理。
失能未确认时必须人工支撑并检查电机/物理急停，不把退出码当作机械安全证明。

UI 只停止自己启动的进程。如果控制端原先从别的终端启动，须在那个终端停止一次，再由总 UI 接管后续启动。
控制器进程和标定严格互斥；退出超时不强杀、不自动重启、不自动进入下一工作流。

方向/参考角不确定时不能跳过前两阶段，完整命令见[完整标定流程](../README.md#calibration)。

UI 角度为度，ROS 为弧度；位置为米。J1..J7 对应 joint_0..6。
输入只编辑草稿，不边拖滑块边发送，不自动切换到位置模式。
专用回零按钮例外：会自动切换并核实关节位置/重力控制器已激活，再下发轨迹。
发送成功只说明话题已发布，**不是 IK 收敛、目标到达或路径安全的确认**。

## 回零与显示

回零位于“运行总览”的控制器下方，可选左臂、右臂、双臂。默认 8 秒，输入范围 3..60 秒。
它使用已标定的关节零位，不发送电机写零指令、不修改标定文件。
后端根据当前姿态生成 50 Hz 五次平滑曲线采样，作为一条 JointTrajectory 发送，
由现有关节控制器分段插值执行。轨迹首点是当前反馈、末点为零；请求时间太短会自动延长，
使理论关节峰值速度不超过 20°/s，日志显示实际时间。这不是实际速度闭环安全限幅。
专用回零允许超过普通编辑目标的 20° 步长限制，但目的地只能是零；其他任意目标限制不变。
单臂只下发该臂七关节，另一臂在关节位置模式下保持原设定；模式切换作用于整个已加载控制器。
动作不做碰撞检查，必须确认整个路径。控制权冲突、标定会话、缺反馈/失能/错误仍拒绝回零。

原显示每 250 ms 拉取全状态并直接跳转姿态，造成约 4 Hz 的阶梯感。
现在 `/api/pose-stream` 用 SSE 单连接以 30 Hz 发送关节反馈，模型在浏览器渲染帧之间插值，
显示缓冲约 65 ms，不外推未知动作、不改变控制目标；日志/表格仍约 4 Hz 更新。
反馈超时或断连时保持最后显示并标为非实时，后台标签暂停模型绘制和姿态流。
关闭持久绘图缓冲、限制像素比、使用轻量材质并缓存关节轴，减少 GPU/分配开销。
网页直接加载 URDF 引用的完整原始 STL，不做减面，不使用 `web/meshes` 的历史实验网格。
之前约 54 万面减到 17 万面的版本破坏了部分薄壁/孔的显示，已撤回该默认加载路径。
高频姿态流、显示插值和其他渲染优化仍保留；控制 URDF、碰撞、惯量不变。
实际渲染帧率仍受浏览器 GPU 加速、STL 复杂度和机器负载影响；显示插值不是机器人状态估计。

## 网页入口约束

- 真机写操作需要服务端授权、页面解锁和逐次确认。总 UI 开放功能，但页面初始锁定、不自动使能。
- 进程入口使用固定命令白名单，不能提交 shell/任意程序/任意文件路径。相同工作区和 ROS 域只允许一个管理实例。
- 新运动请求要求 0.5 秒内对应关节反馈、在线且已使能且 error=1 的 W3 状态、3 秒内的控制器 active 确认。
- 关节目标须在 URDF 限位内，单次相对实测不超过 20 度，插值时间 1..60 秒。
- 末端目标要求 0.5 秒内 TF，单次相对当前位姿不超过 50 mm、10 度。
- 活动标定阻止网页位置控制。有其他目标发布者时拒绝争抢，包括还在运行的遥操作/回放节点。
- 请求串行处理，忙时拒绝；服务超时视为结果未知，不自动重试。等待期间依靠现场急停，不把网页当停车链路。
- 仅检查网页新请求，不补齐底层运行态反馈超时停车联锁，也不监控已发轨迹的整个运动过程。
- 不覆盖原控制算法，无碰撞检查、避障或双臂刚性约束；回零仍需人工确认路径。

记录不切换模式，拖动前应确认重力补偿状态。保存到 workspace/recordings/web_*.yaml，不进入 Git；
反馈过期时停止并保存已有有效片段。预览录制名为 web_preview_*.yaml，不提供真机回放命令，禁止在真机回放合成轨迹。
标定仍由原脚本产生，不上传 Git，不从网页写默认零位。

## 网络与权限

仅监听 127.0.0.1，拒绝其他 Host、跨站写请求，写请求携带每次服务启动生成的随机 token。
没有公开部署选项，不将端口映射到公网，不将 token 当成多用户认证系统。
资源完全本地，不发送模型、标定或日志到外网。SSH 端口转发等同授予访问者控制权限，只用于受信连接。
